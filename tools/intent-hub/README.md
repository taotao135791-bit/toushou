# 意图中台 (intent-hub)

多人 vibe coding 的开工前协调：**每个 AI 在动功能/修 bug 之前先申报意图，中台查重，先到先得拿锁，绿灯才开工**。与团队雷达互补——雷达管"编辑中"的文件级兜底，本台管"开工前"的意图级闸门。

## 为什么需要它

vibe coding 中没人能预知 AI 会改哪些文件，文件级探测是事后信号。意图申报把协调提前到动手之前：撞车在开工瞬间被拦，而不是保存/合并时才发现。

## 部署（服务器管理员，一次）

与团队雷达同机常驻（建议端口 8788）：

```sh
node tools/intent-hub/server.js --port 8788 --repo taotao135791-bit/toushou
```

数据落在同目录 `intents.json`；活跃意图 24 小时未关闭自动过期，防止遗忘死锁。

## 自动解锁（无需任何人配置）

传入 `--repo` 后，服务器每 2 分钟拉取该仓库最近 PR（公开 API，无凭据）：

- PR **合并或关闭** → 对应意图（PR 描述里的 `Intent: #N`）自动解锁，记录 `closedBy=pr#N`
- PR **打开中** → 看板卡片显示 PR 编号徽章（锁继续持有，合并才放）
- 兜底：24 小时 TTL 过期、看板"手动解锁"按钮、CLI `--close`

## AI 使用（已写入 AGENTS.md"意图中台强制上报"）

```sh
# 开工前申报（退出码语义与团队雷达一致）
node tools/intent-hub/cli.js --user 花名 --title "一句话说明要做什么" \
  --scope src/renderer/ads src/shared --branch feat/xxx \
  --server http://<中台地址>:8788
```

| 退出码 | 含义 | AI 行为 |
| --- | --- | --- |
| 0 | 绿灯，已登记（24h 有效） | 静默开工 |
| 2 | 红灯：他人持相似/重叠意图（先到先得） | 停止本次修改，向用户报告持锁人，等指示 |
| 1 | 服务不可达 | 报告一次后继续，不阻塞 |

任务合并后关闭：`--close <id>`；查看全场：`--list`。

## 判定规则（可解释，无黑盒）

- **范围重叠**：任一申报目录与活跃意图的目录互为父子（目录树包含）→ 拦
- **描述相似**：标题+说明的词面重合度 ≥ 30%（中文按二字词组、英文按单词，Jaccard）→ 拦
- 同一用户续报不拦自己；被拦 = 不落库，锁仍归先到者

## 看板

浏览器打开服务器地址即全员实时意图墙（5 秒刷新）。
