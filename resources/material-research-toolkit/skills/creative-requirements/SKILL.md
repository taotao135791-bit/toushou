# 素材需求文档标准（飞书）

目标：产出设计师可以直接执行的素材需求文档。英文只出现在素材执行内容里，说明用中文；结构、附件、去重全部可核验。不编造任何未确认的事实。

## 前置检查（每次任务开始时）

1. **飞书可用吗？** 会话里能看到 feishu_doc_create / feishu_doc_append 等工具且已连接。
   - 未连接 → 回复说明"需要先连接飞书"，并在回复末尾单独一行输出标记 `[[connect:feishu]]`（渲染层会弹引导卡），然后停止等连接。
2. **需要检索参考素材时，MCP 素材服务可用吗？**（名称含 socialpeta 的工具）
   - 未连接 → 输出标记 `[[connect:mcp]]` 并停止；用户只提供内部要求、不需要外部参考时可跳过本条。
3. **飞书工具面能力够吗？** 工具名带"飞书文档"不代表能建原生标题/表格/文件块。写入前先做第九章的三个能力测试；只有纯文本追加能力时按第九章降级方案交付，**不得用 Markdown 管道符或本地路径冒充原生表格和附件**。
4. 就绪 → 按下面标准执行。

## 一、先确认项目事实（缺了就问，一次问全；没确认的不许自行补）

- **投放信息**：媒体（如 Facebook）、地区（未指定就写"建议测试地区"，不能写成结论）、预算（如 USD 200/天）、考核（如 CPI ≤ USD 4）、图片/视频分别多少条、素材语言（如英文）、说明语言（通常中文）。
- **产品信息**：名称与官方链接、实际功能、**不能做什么**、是否涉金融/医疗/借贷/投资等高风险表达、可用的品牌元素与截图。例：Coin.AI 只能做 AI 加密问答/图表理解/概念解释等方向，**不能实际交易**——不得写成交易平台、不得承诺收益/预测价格/交易信号。
- **素材限制**：文档开头用一段中文写明，例：
  > 本批素材不使用真人实拍、真人手部、主持人、手持手机、街拍或剧情类内容；可使用纯 UI、图表、抽象数据图形、3D 图标、2D 图或数字化视觉。
  用户说"不要真人"默认排除：真人脸部/手部/真人操作设备/生活场景街拍/真人口播背书。数字人、2D 插画、纯 UI 是否允许必须单独确认。

## 二、文档层级标准

1. **一个新批次 = 一个独立一级标题**，不能在旧表格下面追加。推荐结构：
   ```text
   # 【新批次标题，如：正在施工中，请勿使用】
   新批次说明 / 投放信息 / 产品边界 / 素材限制 / 去重说明
   ## 新图片素材需求 A｜I01-I05
   ## 新图片素材需求 B｜I06-I10
   ## 新视频素材需求｜V01-V05
   # 原有需求标题（旧批次整体保留在下）
   ```
2. **新批次必须整体连续插在新一级标题下**：找到旧批次一级标题，把新标题+说明+二级标题+表格+附件**连续插在旧标题之前**；不许"标题插在顶部、表格追加到文末"。写入后回读根节点子块顺序确认。
3. **用户指定的标题原样保留**（包括"【正在施工中，请勿使用】"这类措辞），不改近义词。

## 三、表格字段标准

**图片表**（静态素材，禁止口播列）：

| 字段 | 要求 |
|---|---|
| 编号 | I01、I02… |
| 素材参考（SocialPeta链接+本地文件） | SocialPeta 来源、表现信息、本地文件，见下 |
| 中文制作要求 | 构图、视觉、尺寸、替换元素、禁用元素 |
| 素材内英文画面文案 | 画面上实际出现的完整英文文字 |
| 中文翻译（画面文案） | 只翻译画面英文，不添加不存在的口播 |
| CTA与合规边界 | CTA、禁止表达、必要免责声明 |

图片批次说明可加一句：图片为静态素材，不设置口播；视频单独提供英文口播和中文翻译。

**视频表**（画面与口播分开写）：

| 字段 | 要求 |
|---|---|
| 编号 | V01、V02… |
| 素材参考（SocialPeta链接+本地文件） | 同上 |
| 中文制作要求 | 时长、镜头、动画、UI、转场、制作限制 |
| 素材内英文画面文案 | 按时间顺序写完整屏幕文字（如 0-2s / 2-5s / End card） |
| 英文口播 | 完整口播内容，不能只写一句概述 |
| 中文翻译（画面文案+口播） | 分别翻译画面文字和口播 |
| CTA与合规边界 | 结尾 CTA、免责声明、禁用表达 |

**素材参考列只保留一列**，单元格内按序写：
```text
SocialPeta链接：https://...
表现信息：5,361,894 impressions | 90天内检索
本地文件：I09_ui_research_dark.png
[同一单元格内插入飞书原生文件块]
```
文件名必须与实际上传文件一致，不能只写"点击查看"或本地路径。

## 四、文案写作标准

- 英文只出现在画面文案和口播；制作说明/翻译/合规说明一律中文。
- **画面文案必须完整**：主标题、副标题、功能标签、按钮/CTA、免责声明、结尾页文字全部写出，按时间轴分段。
- **中文翻译一一对应**，不重新创作、不省略。
- 参考素材只借鉴构图、节奏、UI 排布、颜色视觉、文案组织方式；**不得复制**原品牌名、资产规模、奖励金额、零手续费、收益率、买卖按钮、用户量、安全/收益承诺。

## 五、SocialPeta 检索与去重（用到参考素材时）

流程：建搜索方向 → MCP 搜近 90 天 → 按限制排除（真人/剧情/交易类等）→ 核对详情与表现字段 → 下载 → 视频抽帧检查（真人/手部/违规场景）→ 与历史来源 URL 去重 → 写入表格。搜索结果是候选池，不能直接当成最终推荐列表。

- 表现信息只能来自实际返回结果（如 `5,875,073 impressions | 90天内检索`）；禁止"效果最好/转化率高/一定能降 CPI"这类无数据表述，曝光量≠安装/转化/CPI。没有可验证数据时只能说"作为参考/表现较高/测试候选"。
- 新批次不得重复旧批次的：SocialPeta 图片/视频 URL、同一素材的不同文件名、明显裁切/改名的同一素材。先收集历史 URL 集合再逐个比对。

## 六、飞书原生附件写入（要求可预览时必须走这条）

标准流程：创建目标表格 → 取单元格 block ID → 在"素材参考"单元格创建**空文件 block** → 取返回的**内部文件 block ID** → 媒体上传（`parent_node` 用内部文件 block ID）→ 将返回的 file token 回写文件 block → 回读确认文件块与预览块存在。

禁止：只写 `D:\...` 路径、只贴网页链接、视频转成不可预览的文本、写了文件名但不上传文件块。视频显示"1B"或转圈 = token 没回写/上传内容为空/字段不对/没有真正的文件块，按第九章排查。

## 七、更新已有文档的安全流程

除非用户明确要求重建，不许清空整个文档。流程：读根节点与所有一级标题 → 定位旧批次标题 → 确定插入位置 → 只删本次要替换的区块 → 插入新批次 → 保留旧批次与无关内容 → 回读核对顺序。重做同一批次必须先清干净该批次的标题/二级标题/表格/附件，避免重复表格和重复文件。

已误写内容时（见第九章 9.6）：先列根节点子块顺序，找到测试标记/空块/重复批次；有删除接口才批量删，没有就向用户说明污染状态，**不许"再追加一份正确的"来掩盖**。

## 八、写入后核验清单（全部过一遍才算完成）

**结构**：新批次独立一级标题｜标题与用户指定文字完全一致｜全部内容在该标题下｜旧批次完整｜图片视频分二级标题｜编号连续。
**表格**：图片表无英文口播列｜视频表有口播列｜图片翻译只对画面｜视频翻译对画面+口播｜参考链接与文件同一列｜文件名与实际上传一致｜没有用户要求删除的字段。
**内容**：英文画面文案/口播完整｜其余说明中文｜无真人手部剧情｜无未确认的收益预测投资建议交易能力｜新旧 URL 无重复｜表现数据来自实际 MCP 返回。
**文件**：每个素材有原生文件块｜token 已回写｜图片可预览｜视频非 1B 占位｜统计数与行数一致。

## 九、写入能力探测与卡点诊断

### 9.1 三个最小能力测试（正式写入前必做，用测试标记验证）

- **测试 A（位置）**：插入唯一文字（如 `【WRITE_POSITION_TEST_260909】`）。接口接受了 `index: 0` 但回读后文字仍在文末 → 不支持位置参数，未知参数被静默忽略。
- **测试 B（Markdown）**：写入 `# 标题测试` 和管道符表格。回读后 `#`、竖线仍是普通文字 → 没有 Markdown 解析能力，不能继续用 Markdown 假装原生表格。
- **测试 C（附件）**：上传一个小测试文件，回读查：文件 block、file token、预览 block、文件大小、能否预览。只看到文件名/1B/转圈 → 附件链路没完成。

**接口返回 ok ≠ 写入成功**——可能只是把内容追加成了普通段落，必须回读验证。

### 9.2 执行路径决策（后台优先，浏览器是备用）

```text
第一优先：飞书 OpenAPI / 本地脚本（block 读取 + children+index 插入 + 批量删除 + 原生表格 block + 媒体上传 + token 回写 + 回读）
第二优先：已授权的飞书文档 MCP，前提是它暴露了原生 block 接口
第三优先：浏览器自动化，仅当 API 不完整且用户明确允许接管浏览器（需网页已登录、窗口保持可用）
降级交付：只有纯文本追加能力时，明确告知用户，交付 Markdown + 本地素材包 + 手动粘贴顺序说明
```

降级时**不能**交付为"已完成"：文末伪标题、管道符文本伪装的表格、只有本地路径的文件、没有 file token 的附件占位、没有回读验证的"已插入"。

### 9.3 常见错误码

**`1770001 invalid param`**：常见于把媒体 token 直接塞进新建 block（image/file 块带 token）。改用 9.4 兼容流程。

**`1770013 relation mismatch`**：token 与文件 block 的父节点关系不匹配（上传时 parent_node 是单元格 ID、回写却用内部块 ID；token 来自别的文档/文件块；重复建块却用旧 token）。**不能只重复 PATCH**：取当前文件块内部 ID → 用它作 parent_node 重新上传 → 用**这次新返回的** token 回写同一内部块 → 回读验证。旧 token 只有 parent_node 完全一致时才可复用。

推荐兼容结构：
```text
单元格
└── view block（通常 33）
    └── 内部 file block（通常 23）
```
不要把单元格 ID 当文件 block 的 parent_node。

### 9.4 文件块幂等修复

先检查单元格现状再动手：
- 无文件 view → 创建空文件块；
- 已有空 view → 复用内部 file block ID，重新上传并回写；
- 已有有效 view → 回读 token 与文件信息，确认无误后跳过；
- 已有错误 view → 原位修复或先清理，**不要追加新块**。

每次执行后输出并核对：
```text
expected_files: 15
preview_views: 15
file_blocks_with_token: 15
failed: 0
```
数量全部回读核验通过，才能报告"文件已插入并可预览"。

### 9.5 权限问题 ≠ 能力问题

docs.write 已授权、建文档和文末追加都成功，但顶部插入/删块/建表格/上传文件失败 → 优先判定**工具面缺接口**，不要反复让用户重授权。只有明确 `401`/`403`/scope 缺失/无权访问目标文档，才是权限问题。

### 9.6 电子表格注意

飞书文档 ≠ 飞书电子表格。表格写入需要真实 `sheetId`，不能想当然用 `Sheet1`/`工作表1`/`0`/`1`。创建接口只返回 spreadsheetToken 时，先找元信息/工作表列表接口；找不到不要反复猜 range。

### 9.7 后台执行安全要求

- App Secret、Bearer Token、file token 不得出现在最终回复；日志只留掩码后的文档 ID/文件名。
- 每次写入前先记录原有结构；每次失败后先回读确认已写入哪些块。
- 超时不盲目重试整批；重试用幂等标记或先检查是否已创建。
- 只有回读验证通过才报告"后台写入完成"。

## 十、交付格式

```text
已完成：
- 新批次一级类目已创建，并确认新内容位于该类目下面；
- 图片 X 张、视频 X 条；
- 图片无口播字段，视频包含英文口播和中文翻译；
- SocialPeta 来源与历史批次已去重；
- 本地文件已作为飞书原生附件插入，可直接预览；
- 已回读核验文档结构和附件数量。

文档地址：{飞书文档链接}
```

说明实际完成了什么、哪些经过验证、哪些未验证；区分"内容已生成/纯文本已追加/原生文档已完成"三种状态，不把候选搜索结果说成已验证效果。**绝不输出 Bearer Token、App Secret、上传 token 等凭证。**
