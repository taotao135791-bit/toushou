# 前端性能验证（未发布）

本轮保持现有功能、会话排序、去重规则、权限及消息归属，只优化数据处理、订阅范围和生产构建。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 相同源码的生产首入口 JS | 1,520,388 字节 | 892,665 字节（减少 41.29%） |
| 首入口 gzip 参考体积 | 341,758 字节 | 264,304 字节（减少 22.66%） |
| 全部 renderer JS | 26,113,488 字节 | 15,846,589 字节 |
| 3,000 条历史记录合并，中位耗时 | 48.81 ms | 1.11 ms |
| 3,000 条会话侧栏查找，中位耗时 | 19.71 ms | 0.81 ms |
| 200 次后台会话更新触发当前聊天提交 | 200 次 | 0 次 |

构建体积使用同一份冻结源码，仅切换 renderer 的 esbuild 压缩选项；Main 与 preload 输出逐字节一致。gzip 仅供体积比较，桌面应用读取的是本地文件，不能据此推算启动时间。次级页面、Office 引擎和 Mermaid 保留已有按需加载方式。

数据处理基准使用本机 Node、合成记录，预热 8 次后测量 30 轮；不是实际账户数据或所有设备上的性能承诺。合并与查找分别对照原实现校验了 30,000 组合成输入，涵盖重复标识、同名不同会话及实时会话覆盖；遇到有歧义的重复记录仍沿用原有首项匹配流程。

渲染对照使用真实 Electron 与 React Profiler，201 个合成会话，逐帧更新后台会话标题和状态 200 次。当前聊天累计 render 时间由约 47.10 ms 降至 0；当前会话改名、状态、只读权限、消息及错误仍能正常更新。该结果只说明减少了无关渲染，不代表整个界面没有其他渲染成本。

验收使用隔离资料目录和本地模拟模型，另检查生产包启动、路由、会话主题、菜单及图表显示。未调用真实广告账户、上传用户数据或使用真实模型凭证。
