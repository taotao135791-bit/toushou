# 投手 v2.4.2

v2.4.2 修复看板刷新与定时任务结算中的四处状态问题；看板生成、日期口径、AF 当天部分数据等能力沿用 v2.4.1。

## 本次修复

- **日期切换后的“假刷新中”**：切换总控日期后，读数模块原本会把“旧结果已失效、但从未失败”兜底成 `pending`，界面显示“刷新中”并禁用模块自己的刷新按钮，实际没有任何请求。现在该状态单独记为“等待刷新”：模块不转圈、按钮保持可点，顶部与模块内同时提示“日期已切换，点击刷新获取新日期数据”。
- **跨看板刷新被静默忽略**：看板刷新锁原本是全局单例，一个看板刷新期间在另一个看板点刷新会直接返回且无提示。现在按看板隔离，各自独立执行。
- **配置未保存完成时刷新无反馈**：本地配置尚未落盘就点刷新，原本会静默取消本次刷新。现在明确提示“看板配置尚未保存完成，本次刷新已取消；请稍后重试”。
- **定时任务把取消记成完成**：会话中止原本只修改内部状态、不广播事件，定时任务无法区分“用户取消”和“正常完成”，于是把取消记为 `completed`。现在中止会广播 `aborting` 状态，任务正确记为“已取消”。

## 升级说明

- 从 v2.4.1 升级：现有看板、数据集、查询配方、账户、项目和模型设置保留。
- 日期切换后的旧结果仍不会冒充新日期数据；界面会明确提示需要手动刷新。
- 任务历史里此前被误记为“完成”的取消记录不会被追溯修改。

## 已知限制

- 看板刷新、日期口径与 AF 当天部分数据的既有边界与 v2.4.1 相同。
- 日期切换只更新口径，仍需手动刷新才会取新日期数据。
- macOS 应用尚未公证，首次打开若被拦截，可右键点击应用并选择「打开」；Windows 未签名，首次安装可能出现 SmartScreen 提示。
