# 2.0.1 修补版

修复 TikTok 已能读数，对话却错误要求重新授权的问题，以及授权回调被无关请求中断的问题。

- 官方 OAuth 已配置时，对话状态不再误报为未配置。TikTok 授权状态与本地数据集写入权限分开判断。
- 从「今日读数 → AI 分析」进入的会话保持只读；要求写入本地看板时会说明需要新建允许本地写入的对话。用户拒绝确认、确认窗口不可用或会话权限变化也会返回明确原因。
- 无关图标请求和不匹配回调不会中断正在等待的授权，正确的 state 校验仍不可绕过。重复回调只兑换一次；取消、断开及重试不会被旧异步请求覆盖。
- TikTok 对话工具统一名称并保留旧会话兼容别名。HTTP MCP 检测支持系统代理和 Streamable HTTP 会话握手，工具发现失败会明确报告；旧式 SSE GET 握手不在此检测范围。

类型检查和全量隔离测试通过：macOS 216 个文件、2082 项通过及 2 项平台跳过，Windows 216 个文件、2084 项通过；22 项 OMP 兼容测试和真实 Electron 合成授权回调、MCP HTTP 交互通过。实际生产包的隔离副本通过原 preload IPC 保存看板和 HTML 布局，退出重启后内容完整恢复；173 个产品代码文件与候选构建一致。真实 TT 只读复测验证了授权账户发现、单日报表的空结果与有指标结果；未修改广告、续期令牌或改写原 MCP 配置，公开材料只保留脱敏结论。

真实浏览器 OAuth 重新授权尚未复测，不能将合成回调测试视为真实重连成功。Google 真实账户、Windows 安装器交互及自动更新的人工验收范围不变；macOS 包仍为临时签名、未公证。

[正式发行构建](https://github.com/taotao135791-bit/toushou/actions/runs/41322595413)及[双平台发行预检](https://github.com/taotao135791-bit/toushou/actions/runs/41321493452)已通过。公开 arm64 ZIP 已重新下载核对版本、图标、架构和校验和；173 个产品代码文件及包内外 TikTok toolkit 与验收来源一致。
