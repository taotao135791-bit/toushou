# AppsFlyer 连接与媒体事件读数

v2.4.3：应用在允许创建会话前先启动本机只读工具入口，授权恢复在后台继续。会话里的入口不会因授权恢复稍晚而永久缺失；每次读取由 Main 等待恢复并检查当前连接，断开或配置冲突时仍拒绝读取。若本机工具入口自身未能启动或旧会话没有安装对应工具，恢复后仍需新建会话。

## 使用

在「连接」中点击「连接 AppsFlyer」，在应用内的独立授权窗口登录并授权，再回到投手。无需创建开发者应用或手填 API Token。首次连接与重新打开授权页使用同一入口；回调仍由主进程校验，取消或断开会关闭本次窗口。断开会删除投手保存的本机授权并移除本机工具入口，不会退出其它浏览器的 AppsFlyer 网站登录。

连接成功后，新对话可以通过随应用提供的只读查询工具查看授权应用及其聚合数据，包括只读和禁止执行命令的会话。例如：「查看这个应用昨天的 TikTok 注册事件，和广告报表放在一起」。助手先读取应用名称以确定范围；未知事件可先查询近期有数据的事件，不能按名称猜测事件定义。已有对话若没有出现新工具，需要新建对话以重新发现工具。

同一邮箱对应多个 AppsFlyer 账户时，OAuth 的账户范围可能与网站当前页面不同。没有授权应用时会返回空列表；有应用但无数据、没有应用访问权限、连接过期及服务不可用分别处理，不能把它们都解释为零。

## 命名数据集（v2.2.2）

对话可将应用、事件、指标、维度、媒体来源与 activity/ltv 口径保存为查询条件，写入 `AF-{名称}` 数据集。看板刷新时会按日期重新拉取已保存的条件；数据卡显示来源。令牌获取使用原有自动续期流程，不将上游令牌交给模型、运行时或页面。

刷新由 Main 按当前看板及各模块的日期规则统一安排。昨日日报与截至昨日的七日趋势使用独立结果槽，复用原查询配方，分别保存本次状态和数据日期；槽位随相对日期滑动复用，不按天新增，也不占用户数据集的 20 个配额。空结果清除旧行，失败不将旧值显示为本次读数。明确截断、达到查询行数上限或历史窗口的部分结果会被拒绝；结束日期为本机今天的窗口可接受标记为部分的数据，并在看板提示截至当前的部分结果。同名数据集已绑定另一查询时拒绝覆盖。

新配方使用完整应用 ID 与名称的稳定哈希标识；已有配方按完整应用与名称匹配，保留原配方 ID 和数据集身份，数据集改名后继续刷新。当前最多保存 20 组查询，达到容量时返回 `query-limit` 并保留旧配方、数据与看板绑定；已有查询仍可更新，不会静默淘汰旧条目。

新业务查询应显式传入 `mediaSources`，使用当前应用真实发现并确认的媒体名称；`[]` 表示该应用全部授权来源。省略参数仅保留旧 TikTok 调用的兼容默认，不能据此将其他媒体方案标成全来源。应用与事件映射沿用当前任务范围；不会因模板、连接成功或其他客户的样例自动建立客户绑定。

历史导入的静态数据若没有保存查询条件，需要通过「接通刷新」补齐应用、事件及筛选绑定；系统先读取真实候选事件，按业务名称匹配，不要求用户提供接口字段。默认创建可刷新的广告看板，明确要求固定快照时才使用手动值。主视图保留业务指标和简短状态，查询参数放在工具详情，不自动生成长篇口径便签。

无具体方向时，业务板采用指标、日期趋势、阶段漏斗、简短分析及媒体对应的兜底方案，日报带表格；明确的用途、风格、结构和后续定制优先。表格当前只绑定一个数据集，不提供媒体与 AF 的实时跨源拼表。漏斗各阶段可引用不同真实数据集；数据分析模块随绑定值重算描述性 highlight，静态便签不会随刷新重写。模块可继承总控、按报表截止日回看或使用独立历史日期；固定历史日期仍可刷新，与固定值快照分别处理。

生成先进入私有草稿，`board_check` / `board_build_preflight` 按应用保存的本次要求检查真实配置、日期与数据状态；模型不能省略要求来绕过。正式保存由 `board_build_commit` 重新验收后整体完成。检查失败会返回缺口，不改成固定数，也不擅自发布低粒度替代板。通过不表示媒体与 AF 的归因定义或数值相同。

## 日报口径

- 应用、广告系列 ID、媒体来源和日期共同确定范围，广告系列名称只用于显示。一个平台的应用 ID 不能直接当作另一个平台的内部应用 ID。
- Count 是事件次数；Unique users 是独立用户数。两者分别保留，不自动相加或替换。
- activity 为活动日期口径；LTV 为归因日期下的生命周期口径。它们可以分别查询，但不能直接当成同一份日读数。
- 每次保留接口返回的时区供详情核对，联调使用项目已确认的业务口径。来源时区不同本身不作为故障，也不反复阻止已确认的联合分析；不能通过改日期标签伪造数据换算。
- 保留币种、事件筛选、部分数据和更新时间。缺失项保持未知；只有接口明确返回零时才显示零。不同币种不直接计算成本。
- Campaign ID 能建立活动关联，但不能证明 AppsFlyer 自定义事件与 TikTok 优化事件相同，也不能证明两平台的归因窗口、SKAN 或回传延迟一致。未确认事件映射时分别标注来源。
- 官方查询按单个应用执行，最多 366 天、300 行、一个指定事件；空事件筛选用于发现事件。达到行数上限可能被截断，不作为完整报表。结构化联调解析会拒绝达到上限的结果。

## 实现和数据边界

官方入口为 `https://mcp.appsflyer.com/auth/mcp`。主进程完成 OAuth 动态客户端注册、PKCE、回调校验、凭据加密与续期。安全存储失败通过现有共享协调器处理，不通过轮询反复触发原生钥匙串读取。

运行时连接到本机的随机能力令牌入口，只有 `get_apps` 与 `analytics_fetch_aggregated_data` 两项只读工具。随应用提供的 AppsFlyer 查询扩展也使用这个入口，并仅注册应用列表和事件查询；不放宽会话的文件写入或命令执行权限。官方 OAuth 令牌不会写入运行时 MCP 配置或返回 Renderer。本机入口只监听 loopback，具有请求体、查询范围和会话数量限制；退出时停服并尽力清理仍由本集成持有的配置。手写同名或被用户修改的配置不会被覆盖。

MCP 配置位于当前运行时配置目录，注册表和独立加密凭据位于应用数据目录；POSIX 下 MCP 配置为 0600。Windows 继承用户目录访问控制，POSIX 权限位不表示已经单独验证 NTFS ACL。

业务结果可由用户选择的模型分析，并进入用户明确要求保存的本机成果。应用不向源代码仓库自动上传账户信息、授权信息或读数。开发测试仅提交虚构数据；真实联调结果、截图与原始报表不得进入源码、测试夹具、提交或公开发行记录。

连接页图标使用 AppsFlyer 官网公开 SVG 原件，来源记录在资源目录中。官方功能、账户权限和配额以[官方 MCP 说明](https://support.appsflyer.com/hc/en-us/articles/36349070304785--Beta-AppsFlyer-MCP)为准。
