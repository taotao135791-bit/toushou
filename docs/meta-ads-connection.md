# Meta Ads 连接（Pipeboard）

在「连接」的 TikTok Ads 下方点击「连接 Meta」，投手打开系统默认浏览器，完成 Pipeboard 登录、Meta 广告账户关联和投手的只读 MCP 授权。等待期间可重新打开本次授权页或取消；成功后提供重新授权与断开连接。

对话只说「连接 Meta / Facebook / FB」、查账户或查广告数据，也默认走该 MCP 连接，无需额外说 MCP。未连接或工具不可用时指引连接页，不能自动退回旧 Ads Manager 浏览器抓数。OAuth 在浏览器完成，与网页抓数是不同流程；旧网页抓数入口、Agent 报表工具及 Main 导出/刷新已暂停，即使旧会话调用也会返回暂停说明；已有报表、本地历史和手动文件导入保留。今日页改为连接入口。通用浏览器及系统 OAuth 不受影响。全局会话基线负责路由，不依赖旧版已安装技能文件是否更新；新建或重新启动会话进程后生效，已运行的旧会话需重开。

## 服务与权限

当前采用 `投手 → Pipeboard Meta Ads MCP → Meta Marketing API`。这是第三方服务，不是 Meta 官方 MCP，也不经过 Muse。授权和广告数据访问经过 Pipeboard；界面明确显示该来源。用户需审核服务条款、授予的账户及权限；本机只读限制不代表 Pipeboard 自身的 Meta 授权必然仅含读取权限，需以真实授权页为准。

- 上游固定为 `https://meta-ads.mcp.pipeboard.co/?read_only=true`。
- OAuth 只请求 `mcp:read`；主进程限定 OAuth 发现、注册、授权、令牌端点，使用公有客户端、PKCE S256、随机 state 和固定本机回调 `http://127.0.0.1:53683/callback`。不需要为投手自行创建 Meta 应用或设置应用 ID。
- 运行时只开放 `get_ad_accounts`、`get_insights`，并使用服务实际 schema。创建、更新、删除、预算、状态工具均不开放。服务方只读参数与本机白名单同时生效。
- Pipeboard 凭据使用独立的加密文件 `meta-ads-pipeboard-credentials.bin`；旧 Meta 官方凭据不读取、不迁移、不发送给 Pipeboard。运行时仅持有本机只读代理能力，不接触上游 OAuth 令牌。
- 连接成功表示 MCP 握手和所需只读工具验证通过，不代表真实广告账户已关联、可读或报表数字已核对。
- 断开删除本机 Pipeboard 凭据，不等于在 Meta/Pipeboard 侧撤销整个平台应用；后者在对应服务设置中管理。
- 同名手写或被其他人修改的 MCP 配置不会被覆盖或删除。

## 验证顺序

先完成浏览器授权，再在新对话中用 `get_ad_accounts` 查看已授权账户；选择明确的测试账户，按实际 schema 查询一小段日期的 `get_insights`。对齐账户、时区、币种、日期、筛选、分页和后台数据后才能确认可用。账户为空、无权、工具报错或付费限制应如实显示，不能把缺失补零。

已有 FB 报表和手动导入保留，旧网页抓数及相关自动刷新已暂停。Meta 投放及平台归因数据，与 AppsFlyer/Adjust 安装、付费、收入数据分别标明来源。

2026-11-04 至 11-05 已验证：公开授权发现、客户端注册、浏览器授权、本机回调、授权恢复及真实 MCP 账户列表和小范围表现查询。工具 schema 已通过真实连接确认。报表与广告后台的逐项核对、账户时区核验和完整分页验收仍待完成；不能将单页样本称为完整报表。

主进程、IPC 和共享连接契约有意变更，合并前需对应负责人审核。

## 默认看板展示

Meta Ads/MCP 看板默认选择 `meta` 本地模板，和 TT 复用本地 `counter`、`chart-line`、`chart-bar`、`note` 组件及网格编辑能力。新建菜单与描述生成提供 Meta 入口；描述中的 TT/TikTok 优先选择原生 `tiktok` 模板，Meta 优先选择 `meta`，不再落到演示广告模板。Agent 创建工具在省略模板时也按名称及说明识别这两个平台；通用空白看板和已有 FB 已保存报表入口保留。

Meta 模板内置 `meta-reading` 读数模块，首次点击「加载账户」，选择一个已授权账户后读取 `get_insights(level: account, time_breakdown: day)`。单模块刷新、整板刷新和总控日期切换共用 Main 只读链路；没有配置账户时不自动读取全部账户。Main 再校验所选账户属于本次授权列表；凭据不跨 IPC。仅开放预定义日期范围和账户 ID，不允许前端传任意工具参数。

总控沿用本机日历日期窗口，Main 转成明确的 `since/until` 日期查询，避免服务预设范围的包含边界差异。返回数字按 Meta 账户统计日，查询起止日期、币种和读取时间显示在模块中。界面提示日期范围使用本机日历：本机与账户时区不同时，「今天」和「昨天」可能与 Meta 后台的相对日期不同，应按显示的具体日期核对。账户列表未提供时区时明确标为待确认。仅展示单账户，避免跨币种混加。消耗、展示、点击为平台投放指标，CTR/CPC/CPM 根据返回值计算，不擅自把 actions 合计成转化。

Main 适配真实 FastMCP structuredContent.result 包装和 Pipeboard segmented_metrics 每日分段报表，不把汇总伪造成每日行。验证明细的账户、日期、指标和分页；最多五页，游标不完整、重复日期、账户不匹配、超出范围或服务错误均不采用本次结果。缺失指标不补零。读数暂存于当前打开模块的内存数据集，按模块 ID 隔离，刷新开始、失败、断开和卸载均清空；关联卡片不会保留旧数冒充新数。未保存真实账户读数到源码或模板，重新打开模块会重新查询。

旧空 Meta 模板顶部提供「启用 Meta 读数」，仅当原六个模块仍为完整空模板时显示，由用户点击替换为空白的实时模板；已填写的快照、HTML 和其他看板不自动覆盖。也可通过添加菜单插入独立「Meta 读数」模块。
默认流程不生成整页 HTML、CSV 或伪造已验证快照；自定义 HTML 文件仍限用户明确要求时使用。已有 HTML 报告不自动转换或覆盖；需要转换时读取实际源数据，逐模块重建并保留旧报告。Main、Shared 与 Agent 工具说明变更，合并前需对应负责人审核。
