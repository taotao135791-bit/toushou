# HTML 自定义看板与分享：V2 方案评估

> 状态：设计评估，不是已发布功能说明。本文件所列 V2 设计、托管分享和对话联动均待实现与验收；本批读数快照与导出以最终代码、测试和发行状态为准。

## 现状与边界

现有看板整体已经是 React 渲染的 HTML 界面，布局由 `react-grid-layout` 管理；部分原生图表使用 SVG，不能把当前看板概括成“整个看板都是 SVG”。看板和卡片有受限的外观字段、预设、数据集绑定和只读对话草稿，详见 `src/renderer/pages/BoardsPage.tsx`、`src/renderer/pages/boards/WidgetBody.tsx`、`src/shared/boards.ts` 与 `src/shared/boardChat.ts`。

现有文件卡可以读取当前授权工作区中的图片或 HTML：Main 校验工作区相对路径、真实路径包含关系和 10 MB 上限，Renderer 将 HTML 放到 `srcdoc` iframe，设置 `sandbox="allow-scripts"` 且不授予 `allow-same-origin`，文件变更可触发刷新（`src/main/boardFiles.ts`、`src/renderer/pages/boards/WidgetBody.tsx`）。这是**嵌入一个受限的现有文件**，不是整个看板的自由 HTML 文档编辑器，也不是可发布的网址；有脚本权限和宿主 CSP 不能被解释成完整网络隔离。

本批工作区变更中的 `reading-snapshot` 保存的是固定日期、账户、来源时间、币种、数值与失败状态，默认脱敏的导出从已保存快照生成独立 HTML/CSS 表格和按平台、币种分组的柱图；没有脚本、SVG、外部资源或自动刷新（`src/shared/readingSnapshot.ts`、`src/shared/readingSnapshotHtml.ts`、`src/main/readingSnapshotExport.ts`）。实名导出必须由用户主动选择；数据数字本身仍可能敏感。它是**下载后的静态文件**，不能据此宣称已支持任意 HTML 自定义、实时数据绑定或托管链接分享。

## 产品方案

建议把可视编辑、HTML 自定义和分享放在同一份版本化文档之上，但分别定义能力：

| 能力 | 建议行为 | V2 预计范围 |
| --- | --- | --- |
| 布局与风格模板 | 选择模板后可调整区块顺序、宽度、色彩、字号和文案；在预览中明确数据日期与状态 | 白名单组件和受限样式；模板可复制、恢复默认 |
| 自定义 HTML/CSS | 高级用户编辑文档的展示层，预览时只接受经过校验的结构和样式 | 离线、自包含、默认不运行用户脚本；交互式脚本是独立的后续能力 |
| 本地导出 | 用户预览后导出独立 HTML；默认隐藏账户名、ID 与自由文本错误详情 | 静态快照，不生成网络链接 |
| 静态链接 | 将一次经过审阅的快照发布到托管服务，生成带权限和有效期的链接 | 需要服务端、身份校验、权限、撤销和删除，当前尚无 |
| 实时链接 | 访问者读取获得授权的数据快照或服务端只读数据 | 另行设计数据同步、服务端身份和权限；不能复用桌面本机凭据 |
| 对话高光 | 用户选中看板/卡片并要求分析，生成可审阅的高光卡片建议 | 需实现与 `boardId`、版本和证据的绑定；不得自动修改投放 |

模板宜提供“运营日报”“客户周报”等起始结构，保留空白模板；数据与视觉主题各自切换。模板中的标题只是显示文本，账户范围、时间窗口、时区、货币和读数状态由经过校验的数据绑定决定，不能靠文案或模型推断。

## 版本化文档与数据绑定

建议新增独立的 `BoardDocument`，不把原始 HTML 当作数据库或把已有 `KanbanBoard` 直接改写为不兼容结构。以下是**拟议示例**，字段名和实现可在 RFC 中定稿：

```json
{
  "schemaVersion": 2,
  "boardId": "board-example",
  "revision": 12,
  "title": "运营周报",
  "theme": { "templateId": "weekly", "tokens": { "accent": "#2763c8" } },
  "sections": [{ "id": "overview", "kind": "metric-table", "bindingId": "reading-1" }],
  "bindings": [{ "id": "reading-1", "source": "snapshot", "snapshotId": "snapshot-example", "revision": 3 }],
  "assets": []
}
```

- 文档包含稳定 ID、schema 版本、revision、受限布局和主题、资源清单及绑定引用；限制字段、大小、节点数量、重复 ID 和未知类型。导入先验证，未知新版保留原始文件并提示升级，不静默丢字段或覆盖旧文件。
- 源数据与展示分离：本地 Main 维护已授权的数据源、账户范围和只读快照；渲染层只获得本次需要的、经过验证的投影，绝不获得访问令牌。文档绑定可引用固定快照或明确授权的本地只读查询；更改主题不会触发广告账户写操作。
- 快照保存每账户平台、日期窗口、采集时间、时区、币种、结果类型、数据完整性和失败/未尝试状态；空值为未知，不替换为零。不同币种、不同结果类型不混合求和或绘制共同标尺；50 个账户分页或分批读取并显示进度和失败。
- 数据刷新是显式操作或用户单独启用的只读计划；刷新不调用大模型。任何涉及费用、预算、广告状态的动作不从文档或网页触发。
- 新增 revision 和乐观并发校验：保存提案附带预期 revision，版本已改变时要求重新预览，避免旧对话覆盖新布局。固定快照应引用具体数据版本，历史版本的展示不可悄悄变成最新值。

## HTML、资源和安全边界

默认导出建议仅使用生成器输出的静态 HTML 和 CSS；模板字体、图标、图片应经授权、大小限制与内容校验后内嵌或打包，离线打开无需 CDN、外链、Cookie、脚本或凭据。导出时默认脱敏名称、ID、标题和可携带身份的自由文本；用户可主动选择实名导出并在保存前看到具体范围。动态广告数值仍可能识别业务，预览中应说明这一点。

高级自定义必须在独立边界中运行：默认拒绝脚本、表单、弹窗、顶层导航和外部连接，HTML/CSS 的标签、属性、URL、`@import` 和资源都要解析并校验，不依赖正则或 `iframe` 单一防线；必须做恶意输入与网络断言测试。Electron 官方建议对不可信内容禁用 Node 集成、启用 context isolation 与进程沙箱、限制导航和新窗口、校验 IPC 发送者，并设置严格 CSP。参见 [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)。

如未来确需脚本交互，应作为明确的独立能力设计，不把 `allow-scripts` 与 `allow-same-origin` 一起授予同源内容；即使使用不透明源，也不能假设 iframe 自身阻止全部网络或凭据访问。参见 [MDN iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe) 和 [MDN 嵌入内容安全建议](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Structuring_content/General_embedding_technologies)。建议在隔离会话里默认拒绝权限请求，并以 CSP `default-src 'none'`、`connect-src 'none'`、`form-action 'none'`、`base-uri 'none'` 等限制资源和外发；实际策略需依据资源模式验证，CSP 是纵深防御而非内容校验替代品。[MDN CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP)

如有宿主与隔离视图通信，先设计最小只读消息协议：仅允许显式的展示数据、限制大小和字段、绑定预期 `window` 与本次会话随机标识、验证来源及请求生命周期；不暴露通用 IPC、文件系统、模型密钥或广告工具。opaque-origin 的 iframe 不能简单依赖 `origin` 字符串作为身份，应结合来源窗口与一次性通道，并专门测试导航后重放。`postMessage` 接收者仍需校验来源和消息内容，见 [MDN postMessage](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)。

## 分享权限与撤销

- **本地 HTML**：用户自己保存和分发；文件脱离应用后可以被复制，应用无法撤回已经下载的副本。更新原看板不会更新该文件。
- **托管静态快照**：明确预览、脱敏范围、接收对象、到期时间后由用户主动发布。服务端用独立随机标识和最小只读 ACL；提供查看权限、失效、撤销和删除，记录必要的审计事件，避免把账户 ID 或令牌放进 URL。不可把“知道链接”误称为强身份验证；如支持公开持有者链接，必须明确其可转发风险。
- **托管实时看板**：单独设计访问者身份、最小权限的数据视图、数据缓存与过期、撤销后刷新失败及授权变更流程。服务端应仅持有为此用途单独授权、可撤销的凭据；分享页面、链接和导出文件不得包含桌面本机广告令牌、DeepSeek 密钥或浏览器 Cookie。明确静态/实时标识和最新采集时间，网络失败显示陈旧或不可用，不伪造零值。
- 指标本身仍可能敏感。发布前应显示将分享的账户数、日期、数据字段、是否匿名和权限；不将测试账户数据、密钥或私有链接提交到公开仓库。

## 对话高光与可审阅变更

用户从某个看板或选中卡片发起分析时，建议传入受限的 `boardId`、固定 `revision`、所选卡片 ID、数据时间窗口与允许的脱敏指标，而非把整个工作区、凭据、全量账户数据或未选中的卡片自动发送模型。界面先展示将发送的范围与 token 预估/实际用量（以实际可获得数据为准）；模型请求由用户触发。

模型可返回结构化 `highlights`：每项包含短结论、证据卡片 ID、证据数据 revision、时间/币种、严重程度、待核实项和建议；不能从未知、失败或未尝试值生成确定结论。高光先作为预览，允许编辑、拒绝或明确应用到当前看板；revision 变化时标记过期并重新核对。点击证据应定位原卡片和对应读数，避免同名账户/活动映射错误；匿名名称与本地真实名称的映射只留在本机，不随模型提示或导出自动发送。

现有 `boardChat.ts` 是有限的看板摘要和待用户应用的卡片提议，不代表已经具备上述 revision 绑定、高光证据校验或实时协作能力。提示模型“只读”不是权限强制；只读需在工具、数据访问和服务端授权层落实。

## 迁移与 V2 发版验收

旧看板、旧文件卡和旧快照继续按现有格式读取；迁移为新文档时创建可回退副本，保留卡片 ID、布局、数据绑定与未知字段，执行原子保存和版本检查。旧版本遇到新版文件应明确提示不能编辑，不能静默降级后覆盖；导出不应反向修改原看板。分阶段上线：先完成离线模板/静态文件、再引入受限编辑与证据高光，最后在权限体系和运维成熟后单独发布托管分享。

V2 验收至少包括：

1. 真实优化师从选择范围、核对异常到生成快照、选择模板、编辑、预览和离线打开导出文件；50 个账户、失败和取消均有明确状态。
2. 每账户日期、时区、币种、结果类型和采集时间可核对；部分缺失、混合币种、不同结果类型不会显示成零或错误总计。
3. 脱敏与实名模式分别验证：账号名/ID、状态详情、标题、资源、图表、HTML 源码与文件名均符合预览；真实账户和密钥不得写入公开测试产物。
4. 断网环境可打开；恶意 HTML、CSS、URL、异常数据和消息不能执行脚本、发出网络请求、读取宿主或调用 IPC。若新增脚本模式，需独立安全评审和自动化验证。
5. 键盘与读屏完整操作，常见桌面宽度、缩放、长名称、多行错误和 50 账户不遮挡；macOS/Windows 正式包分别验收，覆盖旧版升级、迁移失败恢复和并发编辑。
6. 若实现托管分享：身份、ACL、到期、撤销、缓存失效、审计和已下载副本限制均可验证；静态与实时的时间、权限和失败状态清晰。
7. 对话高光绑定正确 boardId/revision/证据，错误或过期证据无法应用；未获用户发送/应用不会调用模型或修改看板，且任何路径都不能修改广告账户。
