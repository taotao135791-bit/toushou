# V2 HTML 看板与对话高光

> 状态：开发中，尚未发行。本文记录已确认范围及实现、验收要求；不表示相关能力已经完成或通过真实账户验收。

## 已确认范围（2026-11-01）

V2 需要支持 HTML 看板自定义、带证据的对话高光，以及本地 HTML 导出。用户已将托管链接移出本次范围：本批不建设分享服务、不部署、不生成固定或实时托管链接。本地导出生成的是用户自己保存和分发的文件，不会随看板更新，也不能撤回已交付的副本。有关后续托管需求需另行确定。

现有工作区中的读数快照保存固定账户范围、日期、来源时间、币种、数值及成功/失败状态，可选择按平台和币种分别绘制 HTML/CSS 消耗柱图；快照导出默认匿名，不自动刷新、不生成网址。实名导出需用户主动选择，即使匿名，指标本身仍可能敏感。快照、模板、HTML 编辑和高光的最终行为，以实现和验收结果为准，不应提前描述为已发布功能。

## 工作流与数据边界

用户应能从固定读数快照选择起始模板，调整允许的 HTML/CSS 展示，预览并保存，再将所见内容导出为可离线打开的本地文件。提供清晰的编辑错误、恢复途径及保存失败反馈，失败时保留当前输入；展示源数据日期、采集时间、币种、状态与快照不会自动刷新。不同币种不求和或共用金额刻度，未知与失败不能绘成零。

开发中的自然语言编辑允许用户描述想要的布局，模型返回建议后先预览；明确采用只把建议放入编辑区，还需用户单独保存。未保存的修改应先保存，失败和取消保留修改说明。生成基于已保存快照，无需重新读取广告账户；受控的指标和图表绑定在本地从该快照填充，不改变原始数据。用户主动生成时，模型可接收所选账户名称、ID、数值、日期、当前布局和用户描述；广告凭据、Cookie 和模型密钥不作为提示内容发送。

为限制模型进程的能力，自然语言编辑使用隔离运行环境。目前支持 `models.yml` 中的 API key 配置和受支持的环境变量密钥；仅有运行时密钥库或 OAuth 登录的模型暂不支持，并应显示明确错误。这是该编辑功能的限制，不改变常规对话或广告平台的 MCP 授权和读数。与 pinned/latest OMP 的兼容探针需要纳入最终代码的 CI，不能凭设计声明全部模型可用。

看板或卡片分析由用户主动发起，产生带来源证据的高光。高光应指向明确的看板、数据版本、卡片或具体数据项与日期/币种；用户预览、编辑并明确应用，过期或不匹配的证据不能静默写入。不能从失败、未尝试或缺失的读数推导确定结论；模型建议不具备广告投放写权限。

本地保留实际账户身份以供用户识别，用户主动请求的模型分析可使用所选账户数据。快照默认匿名导出应排除账户名、ID、可识别标题和自由文本错误详情；图表、文件名和 HTML 源码也要检查。**用户自行编写的 HTML 标题、文字和属性不会自动脱敏**：导出前须逐项检查，匿名快照不代表整份自定义文件匿名。测试源码和公开产物只能使用合成或脱敏数据，不得包含真实账户或凭据。

## 持久化、版本与兼容

Main 是保存边界，应校验所有传入内容、限制大小与结构，使用原子写入，确保失败时不破坏原有看板。模板展示与固定读数分开，修改外观不得改变已保存快照的账户、数值及来源；快照被删除与被偷偷改写是不同操作。每次保存或高光应用应基于受 Main 校验的预期版本，遇到并发冲突保留用户输入并要求重新核对，避免旧预览覆盖新编辑。revision 必须由 Main 管控，不能只依赖 Renderer 声明。

已发布旧版把所有看板保存在同一文件；它不认识新版组件，可能在保存、重排或删除**任何**看板时将整个文件写回，导致新版组件静默丢失。开发中的新版通过独立的 `kanban-boards-v2.json` 隔离：首次使用严格验证旧数据，将原字节复制到新版路径和独立备份 `kanban-boards-pre-v2-backup.json`，保留旧版 `kanban-boards.json`；后续新版保存使用带 schema 版本的格式，不写回原路径。识别到未知或无法安全保留的数据时停止并保留原文件。旧版 columns/cards 的非空备注迁为单独便签，原始模板和时间信息仍在独立备份；详见[兼容说明](multi-platform-readings.md#看板升级和降级开发中)。

降级后旧版看到的是升级前数据；两边后续编辑不会自动合并，旧版再次运行也可能修改原文件。升级、降级或手动恢复前应退出应用并备份全部看板文件，不要把新版文件覆盖到旧版路径。以上隔离、迁移失败提示、恢复以及磁盘写入失败仍须随最终发行包验证；未知未来版本数据不得静默丢弃后写回。

支持的旧版普通看板、文件卡和既有读数应保持可读，保留 ID、布局及数据绑定，并在迁移失败时保留原始文件。对用户不支持的结构应明确提示，不得伪装成空看板。是否做到可恢复回退，以最终实现及跨版本测试为准。

## HTML 与安全边界

自定义内容、导出及预览是不同的信任边界。默认拒绝脚本、表单、弹窗、顶层导航和外部网络访问；标签、属性、CSS、URL、资源和体积需按允许范围解析和验证，不能仅凭正则或 iframe sandbox 假设隔离。导出应自包含、离线可打开，不带凭据、Cookie、本地文件路径或外链。必须以恶意输入及实际网络请求断言验证，不把提示模型“只读”当作安全控制。

现有文件卡可从授权工作区读取 HTML 并放入 `sandbox="allow-scripts"` 的 iframe；这不是默认静态导出的安全证明，也不是新 HTML 自定义编辑器的网络隔离保证。新增编辑器应使用独立的隔离与策略，并限制导航、窗口、IPC、Node、文件及网络能力。参考 [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security) 和 [MDN iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)。

若预览需要与宿主通信，只传递最小的已验证投影，限制消息类型、大小、来源窗口和生命周期，禁止暴露通用 IPC、广告凭据或模型密钥。不能仅凭 opaque-origin 的 `origin` 文本判断对端身份；要测试导航、重复消息和会话结束后的重放。

## 发版验收

1. 用合成数据覆盖模板选择、编辑、保存失败与重试、并发冲突、固定读数及离线导出；50 个账户、长文本、空值、失败和混合币种可正确展示。
2. 对话发送范围、证据定位、版本过期和用户明确应用分别验证；不发送、不应用时不产生对应副作用，不修改广告账户。
3. 验证 HTML 与 CSS 恶意输入、外链、网络访问、导航及 IPC 防护；核对匿名导出文件名、内容、源码和资源，实名选项由用户明确选择。
4. 验证旧版数据升级、迁移失败保留、完整备份与恢复，以及旧版对新版数据的覆盖风险。不能把已知降级丢数据风险描述为已解决。
5. 检查键盘操作、读屏、桌面宽度、缩放、长文本及错误状态；macOS 和 Windows 使用各自构建的正式包验收。真实广告账户仅用于授权的只读验证，记录脱敏汇总；未验证的平台明确说明。
6. 核对同一提交、版本号及发布标签对应的 CI、发布任务、产物与校验和，分别确认 macOS 和 Windows 成功。签名、公证及系统提示以实际包验证结果说明；不得因某一平台发布成功即宣称双平台均已完成。
